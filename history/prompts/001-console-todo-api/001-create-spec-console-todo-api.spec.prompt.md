## Prompt

/sp.specification

Project: Console-Based Todo Application (FastAPI Backend)

Purpose:
Build a console-driven Todo application backed by a FastAPI server.
The console client will interact with FastAPI endpoints to perform all operations.
This phase focuses on API correctness, backend structure, and CLI-to-API interaction.

Target Audience:
- Beginner to intermediate Python developers
- Learners transitioning from scripts to backend services
- Developers preparing for full-stack or AI-agent integration

--------------------------------------------------
System Overview:

The system consists of:
1. FastAPI backend (core logic and data handling)
2. Console-based client (user interaction)

Architecture:
- Console (CLI) → HTTP requests → FastAPI → In-memory storage

No frontend UI or database is used in this phase.

--------------------------------------------------
Functional Requirements:

Todo Model:
- id (int, auto-increment)
- title (string, required)
- description (string, optional)
- completed (boolean, default: false)
- created_at (datetime)

API Endpoints:
- POST /todos
  - Create a new todo
- GET /todos
  - List all todos
- GET /todos/{id}
  - Get a single todo
- PUT /todos/{id}
  - Update title, description, or completion status
- DELETE /todos/{id}
  - Delete a todo

Console Features:
- Menu-driven CLI
- Options:
  1. Add todo
  2. View all todos
  3. View todo by ID
  4. Update todo
  5. Mark todo as completed
  6. Delete todo
  7. Exit
- Clear prompts and readable output
- Graceful error handling

--------------------------------------------------
Non-Functional Requirements:

Performance:
- Must respond instantly for typical CLI usage
- No unnecessary blocking calls

Reliability:
- Proper HTTP status codes
- Input validation using Pydantic
- Consistent API responses

Maintainability:
- Clear folder structure
- Separation of concerns:
  - models
  - routes
  - services
  - cli

--------------------------------------------------
Technical Constraints:

- Language: Python 3.10+
- Framework: FastAPI
- Storage: In-memory (Python list or dict)
- ORM: Not used
- Authentication: Not required
- External database: Not allowed

--------------------------------------------------
Error Handling Standards:

- 400: Invalid input
- 404: Todo not found
- 500: Unexpected server error

Errors must be human-readable and consistent.

--------------------------------------------------
Documentation Requirements:

- Inline code comments
- README.md including:
  - Project overview
  - Setup instructions
  - How to run FastAPI server
  - How to run console client
- OpenAPI docs auto-generated by FastAPI

--------------------------------------------------
Testing Requirements:

- Manual testing via console client
- Optional basic unit tests for:
  - Todo creation
  - Update logic
  - Deletion logic

--------------------------------------------------
Success Criteria:

- FastAPI server runs without errors
- Console client communicates successfully with API
- All CRUD operations function correctly
- Codebase is clean and extensible
