# Implementation Plan: Full-Stack Todo Web Application (Phase II)

**Branch**: `001-fullstack-todo-webapp` | **Date**: 2026-01-14 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-fullstack-todo-webapp/spec.md`

## Summary

Transform the existing Phase I console-based Todo application into a full-stack web application with:
- **Backend**: FastAPI with SQLModel ORM, PostgreSQL (Neon) persistence
- **Frontend**: Next.js App Router with TypeScript, Tailwind CSS styling, Framer Motion animations
- **Goal**: Production-ready CRUD interface with smooth UX and persistent storage

## Technical Context

**Language/Version**: Python 3.10+ (Backend), TypeScript 5+ (Frontend)
**Primary Dependencies**: FastAPI, SQLModel, Next.js 14+, Tailwind CSS 3.4+, Framer Motion 10+
**Storage**: Neon PostgreSQL (cloud-hosted)
**Testing**: pytest (Backend), manual testing (Frontend - Phase II scope)
**Target Platform**: Web browsers (modern, JavaScript-enabled)
**Project Type**: Web application (frontend + backend)
**Performance Goals**: <2s create, <3s page load, <1s update/delete, 60fps animations
**Constraints**: No authentication, shared todo list, CORS-enabled development
**Scale/Scope**: Single todo entity, ~100 concurrent users expected

## Implementation Phases

### Phase 1: Backend Database Integration
1. Add SQLModel and psycopg2-binary dependencies
2. Create database.py with engine and session management
3. Convert Todo model to SQLModel table
4. Update TodoService to use database sessions
5. Add database initialization on startup
6. Test with Neon PostgreSQL connection

### Phase 2: Frontend Foundation
1. Create Next.js application with App Router
2. Configure Tailwind CSS with custom color palette
3. Create TypeScript interfaces for Todo
4. Build API client with fetch wrapper
5. Implement basic TodoList and TodoItem components

### Phase 3: CRUD Operations
1. Build TodoForm component for creating todos
2. Implement toggle completion functionality
3. Add delete functionality with immediate removal
4. Build EditTodoModal for editing todos
5. Handle loading and error states

### Phase 4: Animations & Polish
1. Install and configure Framer Motion
2. Add entrance animations for new todos
3. Add exit animations for deleted todos
4. Add transition animations for completion toggle
5. Ensure responsive design across viewports

### Phase 5: Integration Testing
1. Test full CRUD flow end-to-end
2. Verify data persistence across page refreshes
3. Test error handling scenarios
4. Validate performance against success criteria

## Architectural Decisions

The following decisions were made during planning:

1. **SQLModel over SQLAlchemy+Pydantic** - Single model definition, native FastAPI integration
2. **Next.js App Router over Pages Router** - Modern patterns, better SSR/streaming support
3. **Framer Motion over CSS transitions** - Exit animations, declarative API
4. **React hooks over state library** - Simplicity for single-entity CRUD scope
